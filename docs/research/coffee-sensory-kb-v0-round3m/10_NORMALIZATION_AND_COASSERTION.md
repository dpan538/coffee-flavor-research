# Normalization and co-assertion

## Source-native preservation

The assertion contract preserves source-native wording or, where public
redistribution is not established, its restricted value plus a public SHA-256
commitment. Permitted normalization is limited to Unicode, whitespace,
capitalization, obvious spelling/plural handling, and explicitly reviewed
cross-language equivalence.

No translated descriptor is created to increase vocabulary. The descriptor
census reports 169 source-native forms and 154 conservatively normalized forms;
these are report-receipt counts and are not claimed as independently reproduced
without the missing bundle.

## Co-assertion boundary

Co-assertion events are unordered pairs within one governed P1/P2 effective
record. They cannot cross coffees, mirrors, unrelated judge observations, or
source-family aggregates. Both set-level record counts and pair-edge event
counts are retained.

The census reports 508 supported P1/P2 pair edges across five P2 records. That
figure remains a report receipt until its machine rows are available. The live
adapter pilot computes only from the records it can independently bind to
governed source artifacts.

The live pilot performs no lexical normalization: all 140 normalization rows
are `NOT_PERFORMED_HASH_ONLY_PROVISIONAL`, and both source-native and normalized
form count effects are zero. This prevents hash-only text from being converted
into unsupported public vocabulary.

Independently, the five live Honduras P2 effective records generate 508
unordered within-record pair events from their 73 assertions. This live value
happens to equal the report receipt; it does not import or reproduce the
missing report ledger. Pair generation excludes the 67 unresolved assertions,
cross-record links, and publication mirrors.
