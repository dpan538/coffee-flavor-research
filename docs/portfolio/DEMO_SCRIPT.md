# Demo script

## Two-minute version

**0:00–0:20 — problem and promise**

“Coffee Flavor Atlas is for people who notice sensory differences but struggle
to name them. It is designed as a vocabulary and comparison aid, not a tasting
exam and not an AI that claims one true flavor.”

**0:20–0:55 — current interface**

Open `/`. Show the bilingual editorial framing, then choose “Enter the Atlas.”
On `/atlas`, search for a familiar term, use a category filter, and switch
between index/map/deck views. Open a descriptor and compare it with another.
Explain that these frontend ranges are project-curated pilot data, not
scientific measurements.

**0:55–1:25 — method and status**

Open `/methodology#project-status`. Point out the separation between the mobile
web prototype, validated PostgreSQL foundation, planned user study, blocked
model gates, and implemented public-only PWA shell. The values are generated from governed
repository receipts.

**1:25–2:00 — research correction and next step**

“The project learned that many competition rows were rankings or repeated
publications rather than descriptor labels. It changed the readiness unit to
reviewed assertions and closed human-review self-attestation. The next step is
new evidence: a separately authorized user pilot or rights-cleared descriptor
review—not a decorative deep-learning run.”

## Five-minute version

### 1. User journey (45 seconds)

Describe C0 preparation → seven-level C1 roast → adaptive Q1–Q4 → exceptional
Q5 → five primary and three secondary references. Open `/prototype` and show
that answers can override weak context priors. Clarify that the structured
result is deterministic and auditable, not calibrated probability or a trained
model.

### 2. Interface walkthrough (75 seconds)

- Landing: bilingual purpose and accessible entry points.
- Atlas: query, aliases, category filtering, view changes, and keyboard-usable
  controls.
- Descriptor detail: labels, evidence status, ranges, sources, and editorial
  note.
- Comparison: explicit side-by-side vocabulary exploration.

### 3. Evidence architecture (60 seconds)

Show that professional evidence, industry/commercial language, consumer
language, and future first-party data remain separate. Explain canonical
knowledge versus observations, artifact hashes and locators, effective record
identity, duplicate/publication layers, review evidence, and independent rights
dimensions. The browser does not expose restricted corpus or reviewer data.

### 4. Negative result and redesign (60 seconds)

Explain the sequence:

```text
scale hypothesis
→ consumer-heavy route invalidated
→ competition-native census
→ large publication population but sparse qualified descriptors
→ descriptor-first gate
→ row-level human-review evidence
```

The point is not failure theatre. The acquisition method produced evidence that
the chosen unit and source role were wrong, so the project revised the system
instead of inflating a data claim.

### 5. Future user research and ML (60 seconds)

Show the consented event contract and user metrics: burden, comprehension,
candidate acceptance, abstention, usefulness, recall, and trust. Then show the
model ladder. Deterministic retrieval is current. Statistical, ranking,
embedding, neural, and adaptive-policy levels are blocked until reviewed labels,
rights, grouped splits, and measurable gains exist.

### Boundaries to repeat if asked

- No completed interviews, usability sessions, or participant dataset.
- No model, embeddings, ranking performance, or sensory probabilities.
- Consumer language is not professional ground truth.
- The current app is a mobile-first web prototype; PWA installability is planned.
- The frontend pilot is not a live PostgreSQL view.
