# Constraint registry

Status: permanent architecture source of truth from Round 3F. The executable
copy is seeded in `audit.constraint_registry_entry`; this document explains the
same 35 major rules. PostgreSQL catalog inventory is broader than this semantic
registry: after migration 038 it contains 199 primary keys, 378 foreign keys,
243 unique constraints, 550 checks, 14 constraint-trigger entries and 138
triggers across the eight governed schemas.

Allowed `ENFORCEMENT_LAYER` values are `POSTGRESQL_CONSTRAINT`,
`POSTGRESQL_TRIGGER`, `AUDIT_QUERY`, `CI_GATE`, `CURATION_POLICY` and
`DOCUMENTED_BOUNDARY`. Conceptual boundaries are not misrepresented as database
triggers.

Twenty-five rules are database-enforced, two are audit-enforced, four are CI
gates and four intentionally require curation. Conceptual cross-cultural,
transitive and completeness claims stay outside triggers unless a concrete
write path can be rejected safely.
