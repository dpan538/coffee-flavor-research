# 六道固定题 vs 动态题库：模拟对照（2026-09-20）

owner 的要求：新旧两套流程都保留，就用模拟给这次迭代留下依据；第一轮 200 杯之后，owner 要求扩到 500 条重新验证，并指出需要减轻过拟合。本文是 500 + 500 杯的结果，取代第一轮的数字（见文末「更正」）。结果一节是最终引擎的数字：动态题库（每题 4 个选项，前两题 5 个，R3-D49）+ 近邻补全（R3-D47）+ 第 4 批木质词 + 「卡片跟随读者的信号」（R3-D49）；各项单独带来多少，见后面两节。

- 测试集：`db/scripts/build-simulation-test-set.py`（加 `--cross-source` 生成另一来源的测试集）→ `SIMULATION_TEST_SET.json`、`SIMULATION_TEST_SET_COE.json`
- 模拟：`scripts/simulate-question-flows.mjs`；结果：`QUESTION_FLOW_SIMULATION.json`、`QUESTION_FLOW_SIMULATION_COE.json`
- 留出：`db/scripts/build-dynamic-question-bank.py --holdout <测试集> --holdout <测试集> --out <临时路径>`，近邻索引同样留出：`db/scripts/build-neighbour-index.py --holdout … --out …`，模拟时以 `NEIGHBOURS=<留出的索引>` 传入（仓库里的索引含测试杯，一杯会在近邻里找到自己）；`NEIGHBOURS=none` 是不带补全的动态流程

## 方法

- **两个测试集，各 500 杯，固定种子。** 同来源：CoffeeReview 的评审记录，按烘焙度与冲煮分层（浅烘杯测 225、中烘杯测 100、深烘杯测 75、意式 100），每条至少 3 个已映射概念（平均 3.4 个），带冲煮、烘焙度，以及应用里有对应选项的处理法、豆种、产地。**换来源：Cup of Excellence 的 500 个批次**——另一个机构、另一套用词、每条是评审团的长清单（平均 11.7 个概念）；语境只有「浅烘、手冲」。动态题库的剪枝表几乎全部来自 CoffeeReview，所以第二个测试集专门用来看结论里有多少是那一家的行文习惯。
- **模拟的读者**「喝到的」就是记录里写的东西（12 维向量 + 提到的概念）。两套流程用同一条规则作答：在可以如实选择的选项里，选权重与这杯向量最贴合的那个（也就是这杯里占主导的东西）；动态题的「如实」指该类别确实被记录提到，或该选项不指向具体类别（「还是水果为主」「清甜」）；第二级选记录提到的那个词。两边都有 15% 的随意作答，每杯 3 个种子取平均。勾选时先勾喝得到的词，再按顺序补满 5 个。
- **留出**：动态题库的剪枝表在去掉这 1,000 条记录之后重建。`Matrix_K` 与 16 组参考风味两套流程共用，不偏向任何一边。
- 差值的 95% 区间：成对差值的自助法（2,000 次重抽样）。

## 读法

- **提升在「词」上，而且在另一个来源上也成立。** 终卡的词落在真实子类里：同来源 34.4% → 66.4%，换来源 74.2% → 86.1%；精确到词：10.6% → 31.0%，37.9% → 65.8%。500 杯里动态题库更好的有 444 杯（换来源 290 杯）。这一项不是 CoffeeReview 行文习惯的产物。
- **12 维向量与参考风味这一层，没有可靠的提升。** 同来源更差一些（余弦 −0.028）、参考风味排名不显著；换来源略好。不应对外宣称「更准的向量」。
- **召回有取舍。** 读者指向一个类别之后，卡上的词向它集中（R3-D42 的设计：读者的回答优先），精确度升、覆盖面降。描述词很多的杯子上（换来源，平均 11.7 个概念）召回下降 7.9 个点；评审只写三四个概念的杯子上召回反而上升。
- 代价：平均多问 0.6–0.8 题；同来源上再确认一步开得更多（2.9% → 15.6%），换来源上反而更少（8.3% → 5.9%）。

## 减轻过拟合：做了什么，量出了什么

1. **留出**（上面已述）：剪枝表不含测试杯。
2. **换来源验证**：同一套结论在 Cup of Excellence 上重测。它暴露了一个只在同来源测试里看不见的问题——见文末「更正」。
3. **小样本分组向上一级收缩**（`build-dynamic-question-bank.py` 的 `SHRINK = 60`）：一个分组有 n 条记录，就保留 n / (n + 60) 的自身估计，其余取自上一级分组（上一级同样收缩）。30 条记录的分组三分之二取自上一级，1,500 条的几乎全是自己。68 个分组里 27 个保留的选项因此变化（都是 30–100 条的小组）；两个测试集上的指标没有可测的变化（同来源 62.1% → 62.2%；换来源完全相同——那 500 个批次都落在「浅烘、手冲」这个大组里，收缩碰不到它）。也就是说，收缩没有带来准确度，它换来的是小组的选项不再随几十条记录摇摆。已用于仓库的正式构建。
4. **不学习选项权重**（见下）：手工权重与语料学出来的差不多，少一层拟合。

owner 的问题：手机离可感知的占用还很远，能不能用更复杂的运算换更高的准确度。几种做法都在同一套模拟上量过（数据不含测试杯）。下表是实验阶段的数字（第 4 批木质词加入之前）：

| ------------------------------------------------------------------------------------------ | -----------------: | -------: | ----: | ------------------------------------------------------------------------------------------------------------ |

| 同上，只让**明显**的词领先：近邻里至少 10% 提到、且比率至少是全部记录的 2 倍；其余保持轮换 |              63.8% |    29.8% | 60.2% | **采用**                                                                                                     |

owner 的原则（2026-09-20）：这种方式应该用来强化本身明显但有波动的候选，不是去强化本来就强的候选——后者只会把整体的评价带偏。按出现多少排序，强化的正是到处都常见的概念（cedar、cocoa、orange 各占全部记录的两成，其中 cedar 还是 CoffeeReview 的行文习惯）。所以采用的做法以「相对全部记录的比率」为准：一个词只有在这类咖啡里明显多于一般水平时才稳定领先，不再随轮换时有时无；常见的词不因为常见而得分。

采用之后（最终引擎，含木质词；同一批杯子上「不补 → 补」的成对差值）：

|        | 终卡词落在真实子类                      | 精确到词                          | 召回                              |
| ------ | --------------------------------------- | --------------------------------- | --------------------------------- |
| 同来源 | 62.9% → 64.3%，+1.4（+0.7，+2.0）       | 26.1% → 29.4%，+3.2（+2.0，+4.4） | 57.8% → 60.5%，+2.6（+1.7，+3.7） |
| 换来源 | 86.5% → 86.7%，+0.2（−0.6，+1.0）不显著 | 64.6% → 66.6%，+2.0（+0.1，+3.8） | 37.5% → 38.9%，+1.4（+0.5，+2.1） |

- 多样性基本不变：15,000 条穷举序列里最常出现的词仍是焦糖（30%），可可 19% → 25%，甜橙 16% → 23%，佛手柑 20% → 27%，风干雪松 3.6% → 7.7%；按熵折算的有效词数 62.5 → 59.9，77 个不同的词都还出现。再确认一步的触发率不变（它只看维度）。
- 门槛只试了三组整数值（2 倍 / 5%、2 倍 / 10%、1.5 倍 / 10%），取的是多样性最接近轮换的那一组，没有在测试集上细调。
- 代价：近邻索引随应用下发，182 KB（gzip 后约 90 KB）；每条记录只有量化到 1 字节的 12 维向量与概念编号，不含记录 id、名称、来源、文字与分数。计算约 10 毫秒（电脑）。
- 结论不变：**瓶颈不在算力，在信息**。真正抬高准确度的是多问出来的那一步（第二级问题）；补全添的是 1–3 个点，换来的主要是「同一类咖啡的典型词不再时有时无」。

## 卡片跟随读者的信号（R3-D49）：量了什么，采用了什么

起因：owner 在走查里看到一位答了「柑橘、木头、焦糖」的读者拿到了「水蜜桃」。定位：果香维度在目标向量里有权重（读者的「柑橘」自带果香 1，深烘意式的先验里果香 0.43），而「柑橘」指向整个酸质维度，没有给果香留下线索，两个果香词完全来自轮换——而第一题里读者看过核果、热带水果、果干，选的是柑橘。在 15,000 条穷举序列上：50.3% 的词位由读者指到了词的种类，33.0% 读者给了维度权重但没指种类，16.7% 完全来自先验；81.3% 的卡片至少有一个词来自读者看过却没选的子类。

| 做法（同一批杯子上的成对差值）                        | 同来源：子类 / 精确到词 / 召回 | 换来源：子类 / 精确到词 / 召回 | 结论                                                                                                                                                                                                                          |
| ----------------------------------------------------- | ------------------------------ | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 所有题目里看过没选的子类都排到最后                    | −4.0 / −1.5 / −6.1             | −2.4 / +2.2 / −2.4             | **不采用**：单选题问的是「最像哪一个」，没选不等于没有——选了「木头」并不否定可可；评审记录里一杯咖啡通常同时提到几类                                                                                                          |
| 只在水果一题里这样做（那一题问的就是「哪一类水果」）  | −0.5 / −0.3 / −0.5（均不显著） | −0.3 / +0.3 / −0.3             | **采用**：解决了水蜜桃这类冲突，没有可测的代价                                                                                                                                                                                |

选项数量（owner，2026-09-20）：每题从候选里选出 4 个；只有最前面两题是 5 个，第五个是「说不上来」——正式的选项，不是选项下方的一行小字；苦感只有作为强修正（前四题严重矛盾）时才显示完整五级，平时按烘焙度显示其中四级，余韵同样四级；第二级问题是三个词加「说不上来」。代价分两段量：语料剪枝保留的选项从 4 个到 3 个，同来源子类命中约 64% → 62%、召回约 60% → 57%，换来源约 87% → 84%、39% → 36%（读者喝到的那一类更常不在选项里；两次运行之间还隔着柑橘词那一项改动，所以是约数）；再从「每题 5 个」收到「默认 4 个」没有可测的代价（同来源 −0.1 / −0.3 / −0.3，换来源 0.0 / −0.4 / 0.0，均不显著）。界面清晰换来的这 2–3 个点，记录在案。

## 再确认一步里选中的词必须上卡（R3-D49 后续）

owner 在再确认一步里选了「肉桂」，终卡上没有。定位：那一步显示的是词（每个维度用词表的第一个词代表），读者选的是词；而终卡评价行用的是这一杯轮换出来的词——2,663 次选「肉桂」里只有 466 次卡上写的是肉桂，其余是生姜、八角、小豆蔻；苦感还会因为之前答过「没有明显苦感」而整行消失。现在：在这一步选中的每一个词——不论它属于候选维度还是评价维度——都原样成为终卡上的词（owner：让读者重新确认风味，这些风味至少要有两个出现在最后的描述里，否则反直觉；屏幕上的终卡不显示评价行，所以肉桂这类词也要进词里），排在读者自己勾选的词之前，合计至多五个；超过五个时，多出的评价词才退回导出卡的评价行。已经在词里的词不再重复成评价行。同一处还有第二个问题：再确认之后，卡上的五个词原来直接换成第二次描述的前五个，读者自己勾选的词就此消失（实测：勾了玫瑰、茉莉花、玉兰花、柠檬，确认之后卡上只剩柠檬）。现在卡片保留读者勾选的词，只加上刚确认的候选维度的领头词，不添加读者没选过的词；切换语言时，保留下来的词按所在维度的词表逐位翻译。模拟读者在这一步也改成和别处一样的规则——先勾喝得到的词。上表是这些改动之后的数字：保留读者的勾选让同来源的子类命中从 63.0% 升到 66.3%、召回从 56.5% 升到 58.4%；两套流程共用这一步，所以固定题的数字也随之略有变化。

## 更正（第一轮 200 杯的数字）

第一轮报告过「最近的参考风味排第一 21.3% → 32.7%」。扩到 500 杯并加上换来源的测试之后发现，这个提升有一部分来自模拟读者的作答规则：动态题按「记录有没有提到」作答，固定题按「什么占主导」作答。在描述词很多的 Cup of Excellence 记录上，这条不对称的规则让动态流程的参考风味命中从 57.6% 掉到 31.4%（评审团清单里顺带提到一句茉莉，就被当成了香气主调）。改成两边同一条规则之后：同来源 +3.2（不显著），换来源 +7.3。词层面的结论不受影响，方向与量级一致。

## 局限

- 模拟读者不是真人：它对自己喝到的东西判断得比真人准，动态流程的作答用到了新题目多问出来的信息。真人能否在第二级答得同样可靠，需要真实用户验证。
- 评审每杯只写三四个概念，「没写」不等于「没有」，同来源命中率的绝对值偏低；有意义的是两套流程之间的差。
- `Matrix_K` 与参考风味的构建包含这些测试记录（两套流程共用）。没有语料概念的词（橘子糖、牛轧糖、白巧克力、部分花名）不计入命中率。
